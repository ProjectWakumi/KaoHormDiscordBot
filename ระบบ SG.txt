# 🌸 KaoHorm — Sakura Security Guard
## เอกสารออกแบบระบบและข้อกำหนดการพัฒนา Discord Bot

### 1. วัตถุประสงค์ของระบบ

พัฒนาระบบรักษาความปลอดภัยสำหรับ Discord Bot ชื่อ **KaoHorm** ด้วย Python และไลบรารี `discord.py 2.x` โดยแยกเป็น Cog เพื่อให้ดูแล แก้ไข และเพิ่มความสามารถได้ง่าย

ระบบมีหน้าที่ตรวจจับข้อความที่ส่งเข้ามาในห้อง Security Guard ซึ่งอาจใช้เฝ้าระวังบัญชีที่มีพฤติกรรมผิดปกติ พร้อมบันทึกเหตุการณ์ผ่าน Logger และจัดการห้องรักษาความปลอดภัยโดยอัตโนมัติ

**แนวทางการออกแบบ**
- ธีม Sakura ญี่ปุ่น สีชมพู ม่วง และพาสเทล
- ใช้ Slash Commands
- แยกโค้ดเป็น Cog
- เก็บสถานะและ IDs ในไฟล์ JSON
- ลดการสร้างห้องหรือประกาศซ้ำ
- รองรับการกู้คืนประกาศเมื่อข้อความถูกลบ
- ไม่สร้างห้อง Log Discord ในระยะแรก

### 2. เทคโนโลยีที่ใช้

- Python 3.10 ขึ้นไป
- `discord.py 2.x`
- `asyncio` สำหรับการทำงานแบบ Asynchronous
- `logging` สำหรับบันทึกเหตุการณ์
- `json` สำหรับเก็บข้อมูลการตั้งค่าระบบ
- Discord Slash Commands สำหรับสั่งงาน

### 3. โครงสร้างโปรเจกต์

```text
KaoHorm/
├── main.py
├── cogs/
│   └── SecurityGuard.py
└── data/
    └── security_guard.json
```

**หน้าที่ของแต่ละไฟล์**

- `main.py` — เริ่มทำงานบอท ตั้งค่า Intents และโหลด Cog
- `cogs/SecurityGuard.py` — ควบคุมระบบ Setup, ตรวจจับข้อความ, Banner, Logger และกู้คืนประกาศ
- `data/security_guard.json` — เก็บ IDs ของหมวดหมู่ ห้อง และประกาศ รวมถึงสถานะการเปิดใช้งาน

### 4. คำสั่งหลัก

#### `/security setup`

ใช้ตั้งค่าระบบ Security Guard โดยอัตโนมัติ

เมื่อเรียกใช้คำสั่ง ระบบจะ:

1. ตรวจสอบว่าผู้ใช้มีสิทธิ์ Manage Server
2. ตรวจสอบสิทธิ์ที่จำเป็นของบอท
3. ค้นหาหมวดหมู่ `🌸 SAKURA SECURITY`
4. สร้างหมวดหมู่ใหม่หากยังไม่มี
5. ค้นหาห้อง `🛡️・security-guard`
6. สร้างห้องใหม่หากยังไม่มี
7. ตั้งค่าสิทธิ์การเข้าถึงห้อง
8. ส่งประกาศ Security Guard พร้อม Embed ธีม Sakura
9. บันทึก IDs ลง JSON
10. เปิดใช้งานระบบและบันทึกผลผ่าน Logger

การเรียก Setup ซ้ำควรใช้หมวดหมู่และห้องเดิม ไม่สร้างห้องเพิ่มโดยไม่จำเป็น

### 5. ระบบตรวจจับข้อความ

เมื่อมีสมาชิกส่งข้อความในห้อง Security Guard ระบบจะ:

1. ตรวจสอบว่าเป็นข้อความในเซิร์ฟเวอร์
2. ข้ามข้อความจากบอท
3. ตรวจสอบว่า Security Guard เปิดใช้งานอยู่
4. ตรวจสอบรายชื่อผู้ได้รับการยกเว้น
5. ลบข้อความที่เป็นตัวกระตุ้น หากบอทมีสิทธิ์
6. บันทึกเหตุการณ์ผ่าน Logger เพื่อให้ผู้ดูแลตรวจสอบ

**ข้อกำหนดด้านความปลอดภัย:** การส่งข้อความในห้องดังกล่าวเพียงอย่างเดียวไม่สามารถยืนยันได้ว่าบัญชีถูกแฮ็ก ระบบจึงไม่ควรลบประวัติทั่วเซิร์ฟเวอร์หรือเตะสมาชิกโดยอัตโนมัติจากเหตุการณ์เดียว ควรตรวจสอบความผิดปกติก่อนใช้มาตรการรุนแรง

### 6. ระบบ Banner และประกาศ

ระบบสามารถค้นหา Banner จากห้องและข้อความที่กำหนดไว้เดิม โดยใช้:

- `BANNER_CHANNEL_ID`
- `BANNER_MESSAGE_ID`

ระบบจะนำภาพมาแสดงใน Embed ของ Security Guard หากเข้าถึงได้

สำหรับประกาศ Security Guard เอง ระบบจะเก็บ `message_id` ไว้ใน JSON และตรวจสอบเมื่อได้รับ Event ว่าข้อความถูกลบหรือไม่ รวมถึงตรวจสอบซ้ำเป็นระยะทุก 120 วินาที หากประกาศหายไปจะพยายามสร้างประกาศใหม่

การกู้คืนจะสำเร็จต่อเมื่อบอทยังเข้าถึงห้องและมีสิทธิ์ส่งข้อความกับ Embed

### 7. ระบบ Logger

ในระยะแรกให้ใช้ Python Logger ที่มีอยู่ใน KaoHorm โดยยังไม่สร้างห้อง Log Discord

ข้อมูลที่ควรบันทึก ได้แก่:

- การ Setup สำเร็จหรือไม่สำเร็จ
- การสร้างหมวดหมู่และห้อง
- การตรวจพบข้อความในห้อง Security Guard
- การลบข้อความสำเร็จหรือเกิดข้อผิดพลาด
- การกู้คืนประกาศ
- ปัญหา Permission และ Discord API

ควรหลีกเลี่ยงการบันทึก Token รหัสผ่าน หรือข้อมูลส่วนบุคคลที่ไม่จำเป็น

### 8. ข้อมูลที่เก็บใน JSON

ตัวอย่างโครงสร้างข้อมูล:

```json
{
  "GUILD_ID": {
    "category_id": 123456789012345678,
    "channel_id": 123456789012345678,
    "message_id": 123456789012345678,
    "enabled": true
  }
}
```

ตัวเลขข้างต้นเป็นเพียงตัวอย่าง ต้องใช้ IDs จริงจากเซิร์ฟเวอร์

ไฟล์นี้ช่วยให้ระบบจำห้องและประกาศเดิมได้หลังรีสตาร์ต โดยไม่ต้อง Setup ใหม่ทุกครั้ง ควรสำรองไฟล์และป้องกันไม่ให้ข้อมูลถูกเขียนทับผิดพลาด

### 9. สิทธิ์ที่จำเป็น

สิทธิ์ของบอทควรมีเท่าที่จำเป็น ได้แก่:

- `View Channels`
- `Send Messages`
- `Read Message History`
- `Embed Links`
- `Manage Channels` สำหรับสร้างหรือแก้ไขห้อง
- `Manage Messages` สำหรับลบข้อความ
- `Kick Members` เฉพาะเมื่อมีการพัฒนาระบบเตะในอนาคต

ไม่ควรให้สิทธิ์ Administrator โดยไม่จำเป็น และต้องตรวจสอบลำดับ Role ของบอทด้วย

### 10. ข้อจำกัดของ Discord API

- บอทเข้าถึงได้เฉพาะห้องและข้อความที่มีสิทธิ์อ่าน
- การลบข้อความจำนวนมากอาจใช้เวลานานและติด Rate Limits
- ข้อความเก่ามาก ข้อความใน Threads หรือช่องที่บอทเข้าไม่ถึงอาจจัดการไม่ได้
- สิทธิ์ที่มีอยู่ในเซิร์ฟเวอร์ไม่ได้หมายความว่าบอทจะทำทุกอย่างได้โดยไม่มีข้อจำกัด
- การกู้คืนประกาศไม่สามารถรับประกันได้หากบอทถูกถอดสิทธิ์หรือข้อความถูกลบซ้ำอย่างต่อเนื่อง

### 11. แนวทางพัฒนาต่อ

1. เพิ่มระบบตรวจจับพฤติกรรมผิดปกติและป้องกันการทำงานซ้ำ
2. เพิ่มระบบยืนยันจากผู้ดูแลก่อนเตะสมาชิก
3. เพิ่มห้อง Log Discord เมื่อพร้อม
4. เพิ่มคำสั่ง `/security status` สำหรับตรวจสอบสถานะ
5. เพิ่มคำสั่ง `/security repair` สำหรับซ่อมแซมห้องและประกาศ
6. เพิ่มระบบสำรองและตรวจสอบความถูกต้องของ JSON
7. ทดสอบบนเซิร์ฟเวอร์ทดลองก่อนใช้งานจริง

**เป้าหมายสุดท้าย:** KaoHorm ควรมีระบบ Security Guard ที่ติดตั้งง่าย ทำงานต่อเนื่องหลังรีสตาร์ต ตรวจสอบย้อนหลังได้ และไม่ทำลายข้อมูลสมาชิกโดยไม่มีเหตุผลหรือการตรวจสอบที่เพียงพอ
