# 📘 KaoHorm Discord Bot — Version Manager & GitHub Save System

## 1. วัตถุประสงค์ของระบบ

พัฒนาระบบจัดการเวอร์ชันสำหรับโปรเจกต์ KaoHorm Discord Bot โดยให้ผู้พัฒนาสามารถเรียกใช้งานผ่าน Terminal ภายในโฟลเดอร์หลักของบอทได้

เมื่อพิมพ์คำสั่ง `Save` หรือเรียกใช้งานสคริปต์ ระบบจะวิเคราะห์การเปลี่ยนแปลงของโปรเจกต์ สรุประบบที่เพิ่มเข้ามา ระบบที่แก้ไข และไฟล์ที่ถูกลบ จากนั้นให้ผู้พัฒนาระบุเวอร์ชันและรายละเอียดการอัปเดต ก่อนบันทึกข้อมูลและส่งการเปลี่ยนแปลงขึ้น GitHub

Repository หลัก:
https://github.com/ProjectWakumi/KaoHormDiscordBot

ในระยะแรกให้พัฒนาระบบ Save และจัดการเวอร์ชันให้เสร็จสมบูรณ์ก่อน ส่วนระบบส่ง Log เข้า Discord จะพัฒนาเพิ่มเติมในภายหลัง

## 2. รูปแบบการเรียกใช้งาน

สร้างไฟล์ `save.py` ไว้ในโฟลเดอร์หลักของโปรเจกต์ KaoHorm

ตัวอย่างคำสั่งใน Windows Terminal หรือ VS Code Terminal:

```bash
python save.py
```

หากต้องการให้พิมพ์ `Save` ได้โดยตรง สามารถเพิ่มไฟล์ `Save.bat` สำหรับ Windows เพื่อเรียกใช้งาน `save.py` ได้

เมื่อเริ่มทำงาน ระบบจะแสดงชื่อโปรเจกต์ เวอร์ชันปัจจุบัน สถานะ Git และรายการไฟล์ที่มีการเปลี่ยนแปลง

## 3. ระบบวิเคราะห์การเปลี่ยนแปลง

ระบบต้องตรวจสอบความแตกต่างระหว่างโค้ดที่มีอยู่ในปัจจุบันกับสถานะที่บันทึกไว้ใน Git หรือเวอร์ชันก่อนหน้า

ข้อมูลที่ต้องตรวจสอบประกอบด้วย

- Added: ไฟล์หรือระบบที่เพิ่มเข้ามาใหม่
- Modified: ไฟล์หรือระบบที่ได้รับการแก้ไข
- Deleted: ไฟล์หรือระบบที่ถูกลบออก
- Unchanged: ไฟล์ที่ไม่มีการเปลี่ยนแปลง
- Renamed: ไฟล์ที่ถูกเปลี่ยนชื่อหรือย้ายตำแหน่ง หากสามารถตรวจจับได้

ระบบควรตรวจสอบไฟล์ Python, Cogs, Commands, Events, ระบบ Ticket, ระบบ Security, ระบบ Check-in, ระบบตั้งค่า และไฟล์อื่น ๆ ที่เกี่ยวข้องกับบอท

นอกจากตรวจสอบไฟล์แล้ว ควรช่วยสรุปการเปลี่ยนแปลงในระดับระบบด้วย เช่น เพิ่มระบบ Ticket ใหม่ แก้ไขคำสั่ง `/help` หรือปรับปรุงระบบ SecurityGuard

หากไม่สามารถระบุหน้าที่ของโค้ดได้อย่างแน่นอน ต้องแสดงว่าเป็นการเปลี่ยนแปลงที่ยังไม่สามารถจำแนกได้ ห้ามสร้างข้อมูลหรือกล่าวอ้างว่ามีระบบใหม่โดยไม่มีหลักฐานจากโค้ด

## 4. ระบบกำหนดเวอร์ชัน

หลังจากวิเคราะห์การเปลี่ยนแปลงแล้ว ระบบต้องแสดงเวอร์ชันปัจจุบันและเปิดให้ผู้พัฒนาระบุเวอร์ชันใหม่ได้

ใช้รูปแบบ Semantic Versioning:

- MAJOR เช่น `2.0.0` สำหรับการเปลี่ยนแปลงครั้งใหญ่
- MINOR เช่น `1.2.0` สำหรับการเพิ่มระบบใหม่
- PATCH เช่น `1.1.1` สำหรับการแก้บั๊กหรือปรับปรุงระบบเดิม

ระบบสามารถเสนอเวอร์ชันที่เหมาะสมตามการเปลี่ยนแปลงได้ แต่ผู้พัฒนาต้องเป็นผู้ยืนยันเวอร์ชันก่อนบันทึก

## 5. ระบบจัดการเวอร์ชันซ้ำ

หากผู้พัฒนาระบุเวอร์ชันที่มีอยู่แล้ว เช่น `1.2.0` ระบบต้องแจ้งเตือนว่าเวอร์ชันนี้มีข้อมูลอยู่แล้ว

ให้ผู้พัฒนาเลือกว่าจะดำเนินการต่อหรือยกเลิก

หากยืนยันการเขียนทับ ให้ปรับปรุงรายการบันทึกของเวอร์ชันดังกล่าวในไฟล์ประวัติเวอร์ชัน โดยต้องไม่ลบประวัติ Git commits เดิมโดยไม่จำเป็น

หากเป็น Git tag ที่มีชื่อเดียวกัน ต้องจัดการแยกต่างหากและแจ้งเตือนก่อนเปลี่ยนแปลง เพื่อป้องกันความสับสนในการย้อนกลับเวอร์ชัน

## 6. ระบบบันทึกข้อมูล

ให้สร้างไฟล์หลักสำหรับจัดเก็บข้อมูลดังต่อไปนี้

### `version.json`

เก็บข้อมูลเวอร์ชันปัจจุบัน ชื่อโปรเจกต์ Repository และข้อมูลอ้างอิงการบันทึกล่าสุด

### `version_history.json`

เก็บประวัติการอัปเดตแต่ละเวอร์ชัน ประกอบด้วย

- หมายเลขเวอร์ชัน
- วันที่และเวลาที่บันทึก
- รายละเอียดการอัปเดต
- ระบบที่เพิ่มเข้ามา
- ระบบที่แก้ไข
- ไฟล์ที่เพิ่ม แก้ไข หรือลบ
- Git commit hash หากมี

### `CHANGELOG.md`

เก็บสรุปการเปลี่ยนแปลงในรูปแบบ Markdown เพื่อให้อ่านได้ง่ายบน GitHub

การบันทึกไฟล์ต้องคำนึงถึงความถูกต้องของข้อมูล หากเกิดข้อผิดพลาดระหว่างบันทึก ต้องป้องกันข้อมูลเสียหายและแจ้งให้ผู้พัฒนาทราบ

## 7. ระบบเชื่อมต่อ GitHub

ให้เชื่อมต่อกับ Repository:

`ProjectWakumi/KaoHormDiscordBot`

ขั้นตอนการบันทึก:

1. ตรวจสอบว่าโฟลเดอร์โปรเจกต์เป็น Git Repository ที่ถูกต้อง
2. ตรวจสอบสถานะการเปลี่ยนแปลงและ Branch ปัจจุบัน
3. ตรวจสอบว่ามีสิทธิ์เข้าถึง GitHub และ Push ได้
4. วิเคราะห์รายการไฟล์ที่จะบันทึก
5. แสดงสรุปการเปลี่ยนแปลงและเวอร์ชันให้ผู้พัฒนายืนยัน
6. อัปเดตไฟล์ข้อมูลเวอร์ชันและ Changelog
7. สร้าง Git commit พร้อมข้อความที่สื่อความหมาย
8. Push การเปลี่ยนแปลงไปยัง GitHub
9. ตรวจสอบผลการทำงานและแจ้งสถานะสำเร็จหรือข้อผิดพลาด

ห้ามถือว่าบันทึกสำเร็จหาก GitHub ยังไม่ได้รับการอัปเดตจริง

หาก Push ไม่สำเร็จ ต้องแจ้งสาเหตุเท่าที่ตรวจสอบได้ และเก็บข้อมูลในเครื่องไว้เพื่อให้สามารถดำเนินการใหม่ได้

## 8. ความปลอดภัย

ระบบต้องไม่อัปโหลดข้อมูลสำคัญ เช่น

- Discord Bot Token
- ไฟล์ `.env`
- รหัสผ่าน
- API Keys
- ข้อมูลส่วนตัวหรือข้อมูลภายในที่ไม่ควรเผยแพร่
- ไฟล์ฐานข้อมูลที่มีข้อมูลสมาชิก หากไม่ได้รับอนุญาตให้อัปโหลด

ให้ตรวจสอบ `.gitignore` ก่อนทุกครั้ง และไม่ควรบันทึกไฟล์ทั้งหมดด้วยคำสั่ง Git โดยไม่ตรวจสอบรายการไฟล์ที่จะถูกส่งขึ้น Repository

หากพบไฟล์ต้องสงสัย ให้หยุดการบันทึกและแจ้งเตือนผู้พัฒนาเพื่อยืนยันก่อนดำเนินการต่อ

## 9. ระบบ Discord Log ในอนาคต

ระบบ Log ของ Discord ยังไม่จำเป็นต้องพัฒนาในระยะแรก แต่ควรออกแบบให้สามารถเพิ่มได้โดยไม่ต้องแก้ไขระบบ Save หลักทั้งหมด

เมื่อพัฒนาเพิ่มเติมแล้ว ระบบจะส่ง Embed ไปยังช่อง Log ที่กำหนด โดยแสดง

- เวอร์ชันที่บันทึก
- วันที่และเวลา
- รายการระบบที่เพิ่ม
- รายการระบบที่แก้ไข
- รายละเอียดการอัปเดต
- Git commit hash หรือสถานะ GitHub

ระบบต้องส่ง Log หลังจากตรวจสอบผลการบันทึกแล้วเท่านั้น

## 10. หลักการพัฒนา

- แยกระบบ Version Manager ออกจากโค้ดหลักของ Discord Bot

- ใช้ Git เป็นแหล่งอ้างอิงการเปลี่ยนแปลงของไฟล์
- ไม่ใช้ AI สรุปการเปลี่ยนแปลงโดยไม่มีหลักฐานจากโค้ด
- ให้ผู้พัฒนายืนยันก่อนเขียนทับข้อมูลหรือ Push ขึ้น GitHub
- รองรับการแจ้งข้อผิดพลาดและการบันทึกซ้ำ
- ออกแบบให้เพิ่มระบบ Discord Log ได้ในอนาคต
- ทดสอบระบบกับ Repository สำเนาก่อนใช้งานจริง
